# Project-5-CS4700
## My High-Level Approach
-When my program runs, the main function will execute first. It will retrieve the parameters executed on the command line, for example the port number, server, username, and password.
-Then the program will establish a connection with the TCP socket and send a GET request to the login page
-The login page will send back a response (what is important in this step is that the response will contain a token for the login form, and this token is found using the tokenFindHelper function).
-After that, this token will be sent to make a POST request to the login page. 
-And throughout this process, if the response also has a cookie then I will store it in mapOfCookies (my map to store cookies)
-The next step is to send a GET request to the home page (/fakebook), and the server will send back a response with the page's data. Then I will try to find flags with the helper function flagCheckerHelper, as well as the links to visit using getLinkHelper. I also have a Set data structure to check if the link or flag to be added is already taken; if it is, I will not add it
-After that I have a for loop for the linksFromHomePage. Specifically, I treat linksFromHomePage as a queue, I will pop each path out, make the GET request with this path and then find the links and flags from the response data. This process will be repeated until 5 flags are found.
-After having 5 flags, the program stops and I saved these 5 flags to the secret_flags file

# How you tested your code.
My tests for this project were quite manual in the early stages. I wrote a drafted version of the GET request function and tried calling the server to see what the response looked like, and importantly, to understand what the login form token looked like. After obtaining the token, I drafted a POST function and tested this functionality to understand the server's response. Then, when I had new questions about the format of the links on each page, I drafted a GET request function for the home page and tested several calls to gain insight into the response structure and answer my own questions. I used this process throughout the project; after each request, I would make a call to the server to first check if the function was working correctly and to gain knowledge for the next steps. Lastly, I also performed this testing for finding links and flags, but before that, I used console.log to print out the result to see if the links were being searched continuously and if the flags were being found. After testing many rounds and being sure these two features were working well, I removed console.log and directly stored the flags in secret_flags
